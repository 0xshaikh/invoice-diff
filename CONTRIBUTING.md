# Contributing to invoice-diff

Thanks for your interest! This document explains how to set up the dev
environment, follow the workflow, and get a PR merged.

## Code of conduct

Please read [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) before opening issues or
PRs.

## Setup

Requires **Python 3.10+**.

```bash
# 1. Clone
git clone https://github.com/0xshaikh/invoice-diff.git
cd invoice-diff

# 2. Create a virtualenv (optional but recommended)
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate

# 3. Install in editable mode with dev deps
pip install -U pip
pip install -e ".[dev]"

# Or one-shot:
make install
```

Verify the install:

```bash
invoice-diff --version   # should print 0.1.0
pytest --collect-only    # should discover all test modules
```

## Dev workflow

1. **Fork + branch.**
   ```bash
   git checkout -b feat/<short-description>
   ```
   Branch prefixes: `feat/`, `fix/`, `docs/`, `refactor/`, `test/`, `chore/`.

2. **Make changes.** Prefer small, focused PRs. A single PR should do one
   thing. If you are touching three modules, split it.

3. **Write tests.** Every bug fix needs a regression test that fails without
   the fix. Every new feature needs a happy-path test and one failure-path
   test. For marketplace parsers, add a golden test against a real sample
   CSV.

4. **Run the gates.**
   ```bash
   make lint     # ruff check .
   make test     # pytest
   make test-cov # pytest with coverage report
   ```
   CI runs the same commands on Python 3.10, 3.11, and 3.12 — if it passes
   locally on one version, it should pass on all three.

5. **Open a PR.** Use the PR template checklist. Update
   `CHANGELOG.md` under `## [Unreleased]` if the change is user-visible.
   Bump the version in `pyproject.toml` and `CHANGELOG.md` for breaking
   changes.

## Test commands

```bash
# Full suite
make test

# With coverage
make test-cov

# Just one module
pytest tests/test_parser.py -v

# Just one test
pytest tests/test_parser.py::TestFlipkartParsing::test_basic_flipkart_parse -vv

# Only integration-marked tests
pytest -m integration

# Only slow tests
pytest -m slow

# With live logs
pytest --log-cli-level=INFO
```

## Code style

- **Linter**: `ruff` (config in `pyproject.toml`). `make lint` must pass.
- **Formatter**: `ruff format` (not black). `make format` to auto-fix.
- **Type hints**: required on all public functions and classes. The package
  ships a `py.typed` marker.
- **Docstrings**: Google-style for public API; terse comments otherwise.
- **Line length**: 100 characters (enforced by ruff config).

## Adding a new marketplace dialect

The parser auto-detects the marketplace from the header rather than taking a
`--format` flag, so adding a dialect means extending two data-driven tables
plus a synonym list — no new CLI surface required.

1. Extend `SYNONYMS` in `invoice_diff/parser.py` with the marketplace's
   column names, mapping them onto the universal schema
   (`Order_ID`, `Marketplace`, `Invoice_Date`, `Product_Value`, `Commission`,
   `GST_Amount`, `Forward_Shipping`, `Reverse_Shipping`, `Discount`,
   `Settlement_Amount`).
2. Add detection rules to `_detect_marketplace` — either distinctive
   column-shape heuristics (e.g. Meesho's `Item Price` / `Platform Fee`,
   Amazon's space-free `OrderID`) or column-name markers.
3. Add tests in `tests/test_parser.py::Test<Name>Parsing` covering:
   - marketplace detection,
   - column mapping onto the universal schema,
   - money/date normalisation on that dialect,
   - and that `reconcile` can consume the parsed frame.
4. Add a sample generator in `generate_sample_data.py`.
5. Update the Supported Marketplaces table in `README.md` and `USAGE_GUIDE.md`.
6. Update `CHANGELOG.md` under `## [Unreleased] → Added`.

## Reporting a bug

Please search existing issues first. If the bug is a genuine bug, open an
issue using the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md)
with:

- the smallest reproduction,
- the actual and expected output,
- the Python version and marketplace dialect,
- a minimal CSV if it does not contain confidential data.

## Security issues

**Do not** open a public issue for a security vulnerability. See
[`SECURITY.md`](SECURITY.md) — report directly to the address there.
